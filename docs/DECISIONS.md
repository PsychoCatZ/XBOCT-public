## Не блокирует разработку

Выбор VPS из четырёх, домен/HTTPS, Telegram token и owner ID, безопасная установка имеющегося OpenAI key/model/budget,
точные времена и профиль уведомлений. Разрабатывать с fixture LLM и fake transport.
OpenAI key у пользователя есть; его значение не передано. Реальные API-вызовы в этой
подготовительной работе не выполнялись. Модель и бюджет ещё не выбраны.

## До live-пилота обязательно

Подтвердить сервер и ресурсы, безопасно установить secrets, включить уведомления бота
на телефоне/часах, выбрать модель и предел расходов, показать defaults и получить
правки пользователя. Deploy — отдельный разрешённый шаг. Основной файл документации
не должен содержать production IP, пароли или реальные обязательства.

## Когда пересмотреть архитектуру

Несколько пользователей/реплик, высокий write traffic или сетевое хранилище БД — повод
перейти на PostgreSQL и выделить worker. Сотни записей одного пользователя таким поводом
не являются. Новая LLM меняет adapter и evals, но не правила сроков и историю оплат.

## Реализационные решения этапа 2

Review Codex: перенос актуального лишнего и порядок «сводка раньше обычных напоминаний» приняты; исправлены три случая (сводка без доставки, лимит для catch-up, быстрый рестарт посреди отправки).

| Решение | Где в коде |
|---|---|
| Все исходящие сообщения (ответы, напоминания, catch-up, сводка) идут через `outbox_message`; каждая попытка — строка `delivery` | `scheduling/outbox.py` |
| Повторы: retry_after — как сказал Telegram (не считается попыткой); transient — 1/5/30 минут, затем failed; permanent — failed; unknown — не раньше чем через 30 минут, максимум 2 попытки, затем финальный `unknown` (не «доставлено»). Прерванная отправка = unknown: после захвата эксклюзивного lock восстанавливаются ВСЕ оставшиеся `sending` (быстрый рестарт до истечения lease), в каждом тике — ещё и истёкшие lease | `scheduling/outbox.py`, `runtime.py` |
| Перед каждой попыткой напоминание сверяется с пересчитанным планом (`still_wanted`): выполнение, оплата, продление, отмена, архив или смена расписания — сообщение отменяется | `application/planning.py`, `scheduling/notifier.py` |
| У записи уведомления `planned_at` — идентичность плана, `scheduled_at` — момент доставки; тихие часы и лимиты двигают только второе | `storage/models.py`, миграция 0002 |
| Тихие часы проверяются и в момент отправки: автоматические ждут конца; явно названное время — нет; «Позже» уважает тихие часы, но не лимиты | `scheduling/notifier.py` |
| Опоздание больше 6 ч (от `planned_at`) после простоя → одно catch-up сообщение (последняя стадия по каждому предмету) в пределах дневного лимита, иначе перенос на следующий день. Если в этом же тике создаётся недельная сводка, пропущенное едет с ней: доставлена → `sent`; ещё в пути → решается вместе со сводкой; `failed`/финальный `unknown` → обратно в `pending` и обычный catch-up. Ничего не теряется (review Codex) | `scheduling/notifier.py`, `outbox.py` |
| Одно автоматическое сообщение на предмет в день и не больше 4 автоматических в день (сводка и catch-up считаются): лишнее переносится на следующий день к концу тихих часов, ничего не выбрасывается; несколько напоминаний одного тика объединяются в одно сообщение | `scheduling/notifier.py` |
| Тик: refresh → polling → inbox → сводка и её отправка → диспетчер → отправка. Только подтверждённая сводка подавляет обычные дубли того же дня | `scheduling/runtime.py` |
| Сводка строится из текущего состояния; «напоминание отправлялось» — только по доставленным сообщениям; недели до самого первого запуска не считаются пропущенными | `scheduling/digest.py` |
| `refresh_schedule()` — при старте и при смене локальной даты; дата успешного обновления хранится в `runtime_state`; после сбоя повтор на следующем тике | `scheduling/runtime.py` |
| Владелец — только личный чат с `from.id == TELEGRAM_OWNER_ID`; чужие и групповые обновления сохраняются без содержимого, без ответа | `telegram/inbox.py` |
| Кнопки: токены `dt/do/pd/sz/pc/px` с id и версией; command_id = `cb:<токен>`; сервер проверяет владельца, запись и версию | `telegram/callbacks.py`, `telegram/bot.py` |
