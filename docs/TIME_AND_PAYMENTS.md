# Даты, периоды и приблизительный баланс

## Время

Timezone default Asia/Krasnoyarsk; системный timezone контейнера не определяет сроки.
Сохранять local date для обязательств «до дня» и UTC instant для точного времени.
Date-only просрочивается после конца локального дня; уведомление может быть утром.
«Сегодня/завтра/через неделю» вычисляются от исходного времени сообщения в timezone
пользователя, а не от времени завершения LLM. Результат показать явной датой.
«В течение недели» -> 7 календарных дней; «на следующей неделе» в запросах -> ближайший
следующий понедельник–воскресенье; как срок или напоминание без дня — уточнить, воскресенье
молча не назначать. Явное «до конца следующей недели» -> воскресенье. «На пятницу» -> ближайшая пятница, включая сегодня для date-only;
если указанное время уже прошло сегодня, уточнить, а не молча сдвинуть на неделю.
Неоднозначное «вечером» -> настраиваемый slot 19:00. Смена timezone пересчитывает future
jobs для локальных правил, сохраняет историю UTC и показывает preview пользователю.
DST: nonexistent time -> ближайший следующий valid instant; repeated time -> first
occurrence (fold=0), не два напоминания. Asia/Krasnoyarsk проще, но тесты общего контракта нужны.

## Calendar

Daily/weekly selected weekdays/monthly every N months/yearly. Monthday 29–31 clamp до
последнего дня; исходный anchor не теряется (31 января -> 28 февраля -> 31 марта).
29 февраля yearly -> последний день февраля в обычный год. Каждые 3 месяца —
календарные месяцы, не 90 суток. Оплата до срока закрывает выбранный occurrence;
несколько периодов можно оплатить явным списком/интервалом. Впереди материализовать
минимум 12 месяцев, расширять при запросах за горизонт; overdue не удалять.
Reminder shift ≠ due shift ≠ change recurrence. Перенос одного occurrence не
сдвигает anchor постоянного правила.

## Coverage

Главный факт — coverage_until, первый НЕоплаченный local date (exclusive). С наступлением
coverage_until покрытие истекло. UI говорит «оплачено по 14 января включительно; продлить
не позже этого дня, с 15 января уже не оплачено». Напоминания — см. NOTIFICATIONS.md.
Если пользователь говорит «оплатил до января» без точной границы — уточнить.
«Продлил на 3 месяца» при известном текущем paid-through extends от него; при уже
истёкшем периоде уточнить начало, потому что правила провайдеров различаются.
Не выводить покрытие из суммы, если тариф/правило не сообщены.

## Balance

Расход задаётся пользователем в minor units/day; значение >0. Zero означает расход
остановлен и forecast depletion отсутствует. Negative расход запрещён; кредиты/возвраты
задаются явным adjustment. Поддержать историческую дату пополнения/изменения тарифа.

Счёт на старте требует approximate balance checkpoint с временем. Альтернатива —
явно выбранное «до пополнения считаем почти ноль»; UI помечает допущение. Из суммы
пополнения без этих данных нельзя придумать исходный остаток.

После последней correction replay всех событий по timestamp. Для каждого сегмента:
estimated_balance(t2) = balance(t1) - rate_per_day * elapsed_seconds / 86400;
topup прибавляет сумму, correction заменяет оценку, rate_change задаёт следующий rate.
Использовать Decimal для дробной части расчёта; округлять только вывод.
Это непрерывная модель среднего расхода, не воспроизведение часа биллинга провайдера.

Если estimate >0 и rate >0: days_left=estimate/rate; depletion=now+days_left*86400.
Порог предупреждения default 5 дней. Days_left для UI округлять вниз и обозначать
«примерно». При отрицательной оценке показать «расчётный запас исчерпан», не долг
провайдеру и не факт отключения. Внутреннее отрицательное значение не терять молча:
после прогнозируемого нуля и нового пополнения предложить correction/нулевой старт,
если пользователь не знает, продолжалось ли списание. Это предотвращает бессмысленное
вычитание воображаемой задолженности из свежего пополнения.

Backdated события пересчитывают estimate и jobs. Future checkpoints по ошибке запретить.
Forecast stale: показывать дату последней correction/пополнения и известный rate;
не придумывать автоматическую поправку. Не требовать регулярного ввода точного остатка.

## Проверочный пример

2026-10-08 10:00 +07:00: correction 0 RUB, topup 1200 RUB, rate 40 RUB/day.
Запас 30 дней; threshold 5 дней пересечётся 2026-11-02 10:00 +07:00.
Через 10 суток оценка 800 RUB; topup 400 -> 1200 RUB (30 дней снова).
Изменение rate на 60 в этот момент -> 20 дней. Все даты вычисляет код с injectable clock.
